# Sample discs

Six small disc images made with the full workflow. They are real images with RS03 error
correction, and carry the ready-to-run reader as tools/arv.com; only the "medium" is a custom
17.6 MB one (9000 sectors) instead of a 25 GB BD-R (105 MB in total). The images are **not in
git** (they change on every rebuild): download them from the
[`samples` release](https://github.com/mofosyne/arv/releases/tag/samples) into `discs/` with

```sh
samples/fetch-discs.sh      # downloads every image and checks it against SHA256SUMS
```

`home/`, the archive they were made into, is in git. The content is generated by
`gen_sources.py` (synthetic photos, scans and PDFs; no real personal data).

| Disc | What it shows |
|---|---|
| `TRIP-01_2019_4` | `--set trip`, namespaced folder tags (`place:kyoto`, `event:kyoto-2019`); **public**; kept in Box 1, a second copy at the parents'; appraised (the archivist log) |
| `PROJ-01_2020-2023_L` | `--set project` resolves to **PROJ** through its alias; the vocabulary's `Match` rules added **CODE** and **ELEC**. A **git repository**: its working files plus a compacted `.git` (one pack; no hooks or reflogs), and its commits in `catalog/volumes/PROJ-01_2020-2023_L/git.tsv`, so `arv status` and `arv find COMMIT` recognise it anywhere. Like a real clone it has an executable script and two links, one copied and one only noted. |
| `TAXES-01_2019-2020_I` | **sealed**: later discs carry only its id, dates and location, never its title or file list; kept in the fire safe |
| `SCAN-01_1995-2008_D` | `--set scan --category letters` (under both MEMORIES and RECORDS); made with `--split`, though on this medium it fits on one disc |
| `FAMILY-01_2020_Q` | **a collection's first edition**: `arv collection init` made the folder the workflow folder of *Family photos*; this edition holds 2020. **Retired**: edition 2 replaced it once a copy of it was checked |
| `FAMILY-02_2020-2021_I` | the collection's **second edition**, with 2021 added; a cold copy at the parents' and a **warm** copy "on the NAS" (`arv stored`: the image file, read back and recorded). Made last, so it carries the whole catalogue |

`home/` is the archive's catalogue as arv keeps it: its identity, places with their
temperatures, copies, notes, appraisals, the collection and its revisions, and the events of
everything that happened after the discs were made. The discs were never burned: their copies
are recorded as not read back, so `arv todo` has something to say.

## Try it

```sh
./arv --home samples/home list                 # discs, access level, where they are kept
./arv --home samples/home todo                 # what is owed: read-backs, places
./arv --home samples/home collection show FAMILY   # the collection's editions
./arv --home samples/home location list -v     # places and their temperature: Box 1, the safe, the NAS
./arv --home samples/home sets                 # the vocabulary with disc counts
./arv --home samples/home find letter-2001     # which disc, and where it is
./arv --home samples/home tags                 # folder tags by namespace
./arv --home samples/home list --covers 2019-07-15
./arv --home samples/home keywords TRIP-01_2019_4
./arv --home samples/home where                # the archive's identity

7z x -oFAMILY samples/discs/FAMILY-02_2020-2021_I.iso  # or mount it (Linux: mount -o loop,ro)
cp FAMILY/tools/arv.com . && chmod +x arv.com            # the reader the disc carries (any OS)
(cd FAMILY && ../arv.com find Kyoto)                     # search every disc from this one
(cd FAMILY && ../arv.com verify .)                       # every file against the manifests
(cd FAMILY && sha256sum -c manifest-sha256.txt)          # verify
```

Check the error correction, then damage a copy and repair it, with arv alone (or the disc's
own `arv.com`; any dvdisaster does the same with `-t` and `-f`):

```sh
./arv check --image samples/discs/TRIP-01_2019_4.iso --repair   # whole: nothing to do (not logged: no home)
cp samples/discs/TRIP-01_2019_4.iso /tmp/damaged.iso
python3 -c "f=open('/tmp/damaged.iso','r+b'); [ (f.seek(s*2048), f.write(bytes(100*2048))) for s in (40,600,1500) ]"
./arv check --image /tmp/damaged.iso --repair     # "the image was damaged and is whole again"
cmp /tmp/damaged.iso samples/discs/TRIP-01_2019_4.iso && echo identical
```

Zeroing those 300 sectors (about 3% of the image; sectors 40 to 139 were zeros already, so 200
actually change) is repaired back to a byte-identical image, by arv and by dvdisaster Light alike.

## Notes

- Redundancy varies from disc to disc. RS03 fills whatever the 17.6 MB medium leaves
  after the data, and small discs leave a lot. A real 25 GB disc gets at least
  `--min-redundancy` (default 20%).
- Every disc carries `tools/`: arv's source (about 3 MB) and `arv.com` (about 2 MB). That is
  nothing on a real disc, and most of these tiny ones.
- UDF 2.50 has a fixed overhead that doesn't matter on a real disc but shows on these
  tiny ones: about 1.5 MB (anchors, descriptor sequences, the metadata and its mirror)
  for a one-file folder.
- The `Date` fields are the day these were made; coverage comes from the file dates.

## Remake

```sh
make                                 # once: builds src/udfwrite and src/arv
samples/make-samples.sh              # needs git and a C compiler
```

This replaces `samples/home` and `samples/discs`. The images differ on every run,
because they contain UUIDs and dates. Commit `samples/home` and push, then publish the images
as the `samples` release's assets (needs the GitHub CLI, `gh`, with write access):

```sh
samples/publish-discs.sh
```
